# 尽可能扩大字体覆盖

2.6.0 保留原有四分类。高级扩展和引擎兼容默认关闭，已有方案不会自动改变用途。系统字体表覆盖范围可以扩展；应用私有字体、网页下载字体、图片文字和游戏图集仍可能绕过系统字体集合。

## 1. 先读取设备实际字体

进入“诊断与恢复 → 覆盖情况 → 字体清单”，查看系统和 product 字体表、命名字体族、别名、语言回退、variant、fallbackFor 及生成状态。别名解析到目标字体族后随目标生效，不必为每个别名复制配置。未知字体族应先核对文件用途，再用明确规则配置。

Sony 的 `x-sst`、`x-sst-condensed` 等可识别文字族属于自动扩展范围。`casual`、`cursive`、装饰文字族也可扩展；符号、表情、图标和未知字体族保留原样，避免私用区图标被文字字库接管。推断用途仍需在设备上核对。

## 2. 保留四分类，再配置语言和用途

进入“字体设置 → 扩大字体覆盖”。先打开“扩展到其他系统文字字体族”，再按需要新增规则。普通规则选择 Unicode 文字系统、用途和可选语言/目标字体族；选择“字体与字重”编辑真实文件、九档、连续字重和斜体。

独立中文风格示例：文字系统 `Hani`，语言 `zh-Hans`，用途“衬线”或“等宽”；繁体用 `zh-Hant`，日文汉字用 `ja`，韩文汉字用 `ko`。平假名、片假名和韩文音节另外选择 `Hira`、`Kana`、`Hang`。字体必须含目标字符，等宽列宽还需实际核对。

目标字体族留空时按用途匹配，填入字体族时只匹配这些目标。多项用逗号分隔。规则按列表顺序进入回退链，重叠规则优先使用先列出的配置；尽量使用互不重叠的语言/用途/范围。改变语言不会重新设计字体字形；需导入对应地区字形的字体。

## 3. 主字体加有序补字链

在分类或高级规则的编辑页展开“补字字体链”，添加、编辑、上移或移除补字字体。最多八套，不嵌套。优先使用主字体，再按列表顺序补字，最后保留系统原字库。每套补字可分别指定字重和斜体，引用也包含在方案保存、备份和删除保护中。

补字应与主字体同用途，覆盖主字体缺少的文字，避免塞入无关语言和图标。系统匹配还考虑语言、variant 和字体族，列表顺序不保证压过所有平台评分。编辑页预览显示正在编辑的单套字体；覆盖检查预测码点，设备选字才提供 Android 实际塑形文件证据。

## 4. 开启引擎配置兼容并重启验收

打开“兼容内置 Flutter / Skia 的中文回退”，提交后手动重启。编译器增加分开的 `zh-Hans`、`zh-Hant`、`zh` 以及无语言回退，并为已知命名族增加 `fallbackFor`，兼顾旧 Skia 使用空格拆分语言标签的实现。原有日文、韩文回退保留，具体引擎的语言评分仍需实测。

Android 15+ 的 `family-list` 保留父名称及子字体顺序，子项不会添加 Android 禁止的 name/lang 属性。product 字体在系统补字中使用经过哈希校验的副本，保留原字符和表数据。

这一步只改变字体配置，未实现通用应用私有字体 Hook。使用系统集合的应用可共同受益；自行注册资产字体的引擎需要引擎级适配，版本差异再按证据处理。无需一开始就逐个应用加规则。图片文字必须修改图片资源。

## 5. 表情、符号和图标分别配置

新增独立“彩色表情”“数学与技术符号”或“图标”规则。Emoji 保留文字主字体中的数字、版权符号等文本形式，由 Minikin 的序列/样式选择表情回退；需彩色字体，仍要验收 ZWJ、肤色、旗帜、键帽和变体选择器；符号不能替代 Emoji；图标必须指定具体字体族且确认私用区码点含义一致。应用资产图标不受系统字体族规则控制。

字体重写保留原轮廓、度量、GSUB/GPOS、彩色表，过滤后保留有效 Unicode 变体序列。支持 SFNT/TTC 的 cmap 4、12、13、14；不处理 WOFF 压缩文件。数据存在不表示所有 Skia/Android 版本支持其彩色或塑形格式。

## 6. 分层核对结果

依次使用“检查当前方案”“设备实际选字”“检查应用字体来源”。

- **静态覆盖预测**：临时编译、不应用配置，列出计划接管字体族和所选字体能覆盖的码点。不是完整 Android 语言、字重和组合序列评分模拟。
- **Android 实际选字**：API 31+ 对样本文本塑形并返回 glyph、字体文件、TTC 索引、字重和方向分段。独立进程优先重建 FontManager 配置，`fontMapSource` 标明来源；API 29–30 仅报告 `hasGlyph`。此证据不代表应用旧缓存或内置引擎。
- **应用字体来源**：读取目标进程的映射字体和 Unicorn/Flutter 等库。加载文件不证明某段文字实际使用该字体；内存资产、动态解码字体也可能不在文件清单里。

提交方案、重启后检查通知、桌面、阅读、终端、WebView 和常用应用。若只有部分应用异常，记录版本、位置、目标文字和映射来源，再确定引擎或私有字体适配。

## 本次 Sony / 淘宝验证的边界

Android 12 Sony XQ-AT52 的独立 Android 塑形诊断已对“美食外卖”“超市便利”“韩国炸鸡啤酒屋”返回当前 HFC 中文字体文件。淘宝 10.50.10.3 的对应区域先前位于 UnicornView，未捕获目标文字的最终 Unicorn typeface。不能将 Android 系统诊断当作淘宝已修复。本轮没有安装新版模块、应用新字体配置或重启手机。

Unicode 数据固定为 16.0.0，来源和 SHA-256 在 `internal/engine/unicode-sources.json`；使用 `python tools/generate_unicode.py` 可重新生成，支持 `--source-dir` 使用已有源文件。构建过程不下载 Unicode 数据。
