# 应用字体豁免

2.7.0 在“字体设置”底部增加“应用豁免 · 使用原生字体”。点击“读取已安装应用”，搜索应用名称或包名并多选。名单随当前方案的草稿、提交、预设、JSON 导入导出和完整备份保存。点击“提交更改”后手动重启。默认名单为空；未选择的应用继续全局替换。

## 支持条件

- Android 12–15（API 31–35）、arm64 / x86_64，必须启用 Zygisk。本模块的基本字体替换仍支持 Android 10+。
- 名单最多 128 个包名。包名作用于相同 app ID 的各用户安装；面板枚举设备主用户应用。名单应用的普通主进程与子进程按 UID 和应用数据目录归属匹配，不依赖进程显示名。
- 共享 UID 必须选择该 UID 的全部应用；否则该组不启用豁免并报告原因。系统核心 UID、isolated UID、无应用数据目录的进程不匹配；独立 WebView / isolated / SDK sandbox 不保证继承豁免。
- 更改名单、安装卸载或重新安装应用后，提交并手动重启。开机数据库中的不存在包名不启用豁免。数据目录包名与 app ID 双重校验避免普通 UID 回收误匹配。
- 恢复系统字体的方案无需挂载豁免资源，因为所有应用已经使用系统字体。

## 执行方式与性能

开机时读取 PackageManager 维护的 `packages.list`，在暴露 HFC 覆盖之前，用独立 Java 进程构建原生预装字体映射。构建过程不需要尚未启动的 FontManager 服务。保存一份只读序列化映射和小型 XML；字体文件继续使用原字体目录的 bind 镜像，避免复制整套字库。下载的系统字体更新与 OEM 私有主题字体不属于“原生预装”保证。

应用启动时读取有上限的名单文件。普通应用继续执行原有兼容逻辑，并请求卸载本模块原生库。命中应用在私有 mount namespace 内恢复原生字体目录和物理 XML，挂载传播先设为 private；不会使用卸载其他模块的 `FORCE_DENYLIST_UNMOUNT`。

Android 12+ 在应用绑定时接收系统字体映射，覆盖在 pre-specialize 阶段重建的 Java 字体，因此仅恢复字体文件不够。豁免应用临时 Hook `SharedMemory.nGetSize`，识别 `fontMap` 的 memfd 或 ashmem 区域名，替换完整缓冲区文件描述符及大小，保留对应的字体族名称表。首次替换后立即用原函数重新注册，关闭保留的 FD 并解除诊断页映射。没有文字绘制 Hook、后台线程或轮询。

Hook 过的豁免进程仍保留小型原生库映射，不能请求 Zygisk 在 specialization 后卸载尚可能被回调的库；未命中的应用可正常卸载。本机双架构库约数十 KiB；Android 12 Sony 实测原生映射 600352 字节，多个应用共享同一份文件页。仍有进程自己的字体对象、页表及少量启动系统调用，不宣称零开销。若系统从未发送对应映射，初始化适配保持等待，诊断会显示 `awaiting-font-map`，不能宣称豁免已完成。

## 诊断与失败处理

面板分别显示草稿名单、本次开机启用 UID 与共享映射是否已准备。选中应用旁的“检查豁免”按需读取当前存活进程的记录，校验 PID 启动时间；不常驻监控。

里程碑：`files-restored` 表示私有文件视图恢复，`font-map-substituted` 表示完整字体映射 FD 替换，`initialization-hook-removed` 表示初始化 Hook 已撤销。这些证据不代表每一个控件或内置 Unicorn / Flutter 字体已验收。应用内置私有字体仍由应用自己决定。

启动准备失败发生在全局覆盖暴露前，现有挂载回滚机制保留系统字体并报告错误。进程文件恢复失败时撤销本次初始化 Hook，回滚本次新增挂载并记录失败，不把部分恢复标成成功。没有可用 Zygisk 时只有“开机准备”证据，目标进程不会出现成功里程碑。

## 验证边界

2026-11-17 在已连接的 Sony XQ-AT52 / Android 12 / API 31 上，用隔离的 root mount namespace 测试了与实现共享的文件恢复和 FD 替换函数。输入的替换映射为 1411836 字节，换入原生映射为 600352 字节；中文测试文字“美食外卖超市便利韩国炸鸡啤酒屋”实际塑形使用 `NotoSansCJK-Regular.ttc`，英文数字使用原生 Roboto，未出现 HFC 字体或缺字。应用枚举返回了名称、包名和 UID。

该测试不是实际 App 经 Zygisk 启动的完整验收：未安装新模块、修改手机方案或重启，也未验证 Android 13–15、实际 Zygisk 注册、各 OEM、WebView 与 isolated 进程。双架构构建和静态测试不能替代这些运行验证。
